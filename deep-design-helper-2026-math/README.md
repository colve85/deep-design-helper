# 깊이 있는 수업·평가 설계 도우미 — 수학 과목 확장판

「2026 깊이있는 수업 평가 설계 연수생용 워크북」의 **목표 → 평가 증거 → 학습 경험** 설계 흐름을 적용한 교사용 웹앱입니다. 결과를 JSON과 한글 문서(.hwpx)로 내려받습니다. 기존 v2.3.0을 바탕으로 만든 **v2.4.0 별도 수정본**이며 원 제작자와 MIT 라이선스를 유지합니다.

## 변경 사항

- **15개 과목 · 53개 탐구 단원 · 212개 수업 소재 카드**. 카드 수는 고유 교육과정 내용요소 수와 다릅니다.
- 기존 공통수학1·2의 18개 단원·72개 카드를 유지하고 13개 과목의 35개 탐구 단원·140개 카드를 추가했습니다.
- 추가 단원마다 수치 자료, 핵심 질문, 평가요소, 수행과제, 3수준 루브릭, 4차시 흐름, 오개념 발문, 교사용 예상 결과, 조건 변경 전이 과제를 제공합니다.
- 성취기준 원문을 단원별로 수정하면 AI 프롬프트·미리보기·한글 문서에 반영됩니다. JSON에도 수정 내용이 보존됩니다.
- 단원별 작성 내용을 보관·복원하여 과목을 바꿀 때 설계 내용이 섞이지 않도록 했습니다.
- 워크북의 3수준 루브릭과 기존 앱의 4수준 루브릭을 모두 점검합니다.

|구분|과목|탐구 단원|
|---|---|---:|
|기존 공통|공통수학1, 공통수학2|18|
|추가 기본|기본수학1, 기본수학2|6|
|추가 일반선택|대수, 미적분Ⅰ, 확률과 통계|9|
|추가 진로선택|미적분Ⅱ, 기하, 경제 수학, 인공지능 수학, 직무 수학|14|
|추가 융합선택|수학과 문화, 실용 통계, 수학과제 탐구|6|

대표 소재: 관람차 높이, 상자 부피 최적화, 경보·불량 분할표, 바람 속 이동, 이미지 거리와 예측 오차, 타일 발주량, 급식 대기 모형. 전체 신규 자료는 [과목별 수업 소재 목록](docs/math-lesson-catalog.md)에 정리했습니다.

## 원문과 예시의 구분

**추가 과목의 성취기준란은 교사 재구성 목표 초안이며 공식 원문·코드가 아닙니다.** 교육과정 성취기준·해설·성취수준을 대조한 뒤 왼쪽 **성취기준 원문 입력·수정**에 `코드 | 원문` 형식으로 입력하세요. 기존 공통수학 성취기준은 원 저장소의 자료를 유지했습니다.

탐구 단원명과 영역 묶음은 수업 설계용 구성입니다. 모든 과목의 모든 내용요소를 망라한 대조표는 아니며 중학교 수학, 전문 수학·이산 수학·고급 과목군은 포함하지 않았습니다. 각 4차시는 탐구의 예시이며 개념 도입과 연습에 필요한 전체 시수와 다릅니다.

신규 수치 자료는 가상·모형 자료입니다. 워크북의 구조를 적용하여 새로 작성한 수학 예시이며 워크북 사례의 전사가 아닙니다. 루브릭은 공식 성적등급과 자동 대응하지 않습니다. [워크북 반영 안내](docs/workbook-mapping.md)를 참고하세요.

## 사용 순서

1. 과목 → 영역 → 탐구 단원을 선택합니다.
2. 성취기준 원문과 대상·차시·학급 상황을 입력합니다.
3. **모든 단계에 예시 채우기**로 초안을 불러와 수정합니다.
4. 목표·핵심 질문을 정하고 평가요소·증거·수행과제를 먼저 설계합니다.
5. 3단계 소재 카드의 목표·증거를 확인하여 차시표에 넣습니다. 최종 수행에 필요한 적용 → 탐색 → 발견 활동을 역순으로 검토합니다.
6. 설계 점검·미리보기를 확인하고 JSON 또는 한글 문서를 내려받습니다.

카드에는 교사용 예상 결과도 포함됩니다. 학생용으로 배포할 때는 정답·교사용 안내를 편집하세요. 설계 점검 점수는 문구·구조 점검이며 수학적 정확성이나 수업의 질을 인증하지 않습니다.

## GitHub 업로드와 실행

압축을 푼 뒤 **이 README가 있는 폴더의 내용 전체**를 저장소 루트에 올리세요. `src`, `api`, `lib`, `tools`, `docs`, `public`, `.github`와 루트 설정 파일이 모두 필요합니다. ZIP 자체만 올리면 소스로 배포되지 않습니다. 점으로 시작하는 파일도 포함하세요.

기존 저장소에 반영한다면 새 `UnitsExtendedMath.gs`뿐 아니라 `Code.gs`, `Api.gs`, `Script.html`, `Stages.gs`, `Index.html`, `lib/gas-runtime.js`, 문서·검증 파일도 함께 반영합니다.

이 앱은 서버 API가 필요하므로 **현재 구성 그대로 GitHub Pages에서는 실행되지 않습니다.** GitHub에 소스를 보관하고 Vercel 또는 Google Apps Script에서 실행합니다.

Node.js 18 이상에서 외부 npm 패키지 설치 없이 확인할 수 있습니다.

```bash
npm run verify
npm run dev
```

`http://localhost:8080`으로 접속합니다. `Index.html`을 파일로 직접 열면 서버 호출이 작동하지 않습니다.

**Vercel:** GitHub 저장소를 연결하고 Framework Preset은 Other로 선택합니다. 저장소의 `vercel.json`을 사용합니다. [배포 안내](docs/deployment.md)를 참고하세요.

**Apps Script:** `src`의 `.gs` 파일 **9개**, `.html` 파일 **3개**를 모두 추가합니다. 새 `UnitsExtendedMath.gs`도 필요합니다. clasp 사용 시 `.clasp.json.example`을 `.clasp.json`으로 복사하고 본인 scriptId를 입력합니다. 실제 연결 설정은 업로드하지 않습니다.

AI 없이 예시 편집·소재 불러오기·문서 출력을 사용할 수 있습니다. 자동 생성은 본인 Gemini 키가 필요하며 키가 없으면 프롬프트 복사·결과 붙여넣기를 사용합니다. Node 배포는 키를 브라우저에 보관하고 요청 시 서버를 거쳐 Gemini로 전달합니다.
